# RemnaSuper

Интерактивная Bash-утилита для установки, обслуживания и диагностики
`RemnaNode` на Linux-сервере. RemnaSuper объединяет часто используемые
операции администратора в одном меню: управление Docker Compose, логами,
сетевыми обходами, geofiles, сертификатами, защитой SSH и диагностикой
доступности сервисов.

Основной сценарий — администрирование уже установленной
[RemnaNode](https://github.com/remnawave/node), хотя часть пунктов помогает
подготовить и диагностировать сервер без неё. RemnaSuper работает от `root`
и может менять системные настройки, Docker Compose, systemd, cron, firewall и
файлы конфигурации. Перед действиями, меняющими систему, меню показывает
описание операции; перед изменением Compose создаётся резервная копия.

## Возможности

- Генерация ключа Ed25519 и отключение входа по паролю после проверки
  нового SSH-подключения.
- Первичная настройка Debian/Ubuntu-подобного сервера:
  `apt-get update`, `apt-get upgrade`, установка `cron`, `mc` и `wget` с
  последующей автоматической перезагрузкой.
- Установка официального `remnawave-reverse-proxy`.
- Установка `rkn-guard` для фильтрации адресов сканеров через `iptables` и
  `ipset`.
- Смена порта взаимодействия RemnaNode с панелью с обновлением UFW-правила.
- Подключение сертификатов из `remnawave-nginx` к `RemnaNode`.
- HTTP 301 с порта 80 на HTTPS: открытие `80/tcp` в UFW, добавление
  серверного блока в `/opt/remnanode/nginx.conf` и перезапуск RemnaNode.
- Отключение IPv6 на существующих и новых сетевых интерфейсах с сохранением
  настройки в `/etc/sysctl.d/zzzz-remnasuper-disable-ipv6.conf`.
- Добавление заголовка HSTS в TLS server-блоки `nginx.conf` с резервной копией,
  проверкой конфигурации и перезапуском RemnaNode.
- Установка и настройка `fail2ban` для SSH.
- Исправление и подключение логов RemnaNode с настройкой `logrotate`.
- Управление [ss-zapret2](https://github.com/vernette/ss-zapret2):
  установка, поиск стратегии через `blockcheck2`, ручная настройка и удаление.
- Управление Tor:
  локальный SOCKS5, смена цепочки через `NEWNYM` и готовый Xray outbound.
- Управление Psiphon через
  [vps-psiphon](https://github.com/Chara-Freedom/vps-psiphon):
  установка, регионы, ротация выхода, watchdog, логи и outbound.
- Установка geosite/geoip-файлов из наборов Loyalsoldier и xray-routing
  с ежедневным обновлением через cron.
- Управление [Node Accelerator](https://github.com/jestivald/node-accelerator):
  оптимизация, защита, диагностика, CLI-отчёты и откат установленных модулей.
- Встроенная проверка доступности Discord, YouTube, Telegram и Instagram.
- Просмотр ошибок и access-логов Xray.
- Проверка нового сервера через `Node Precheck`.
- Дополнительные диагностические команды `ipregion`, `IP Check Place` и
  `bench.sh`.
- Автоматическое обновление самой RemnaSuper из GitHub.

## Требования

### Базовые

- Сервер Debian/Ubuntu с Bash, GNU-утилитами, `apt-get` и `systemd`.
- Права `root`; обычно программу запускают командой `sudo rs`.
- Для установки RemnaSuper: `curl` и `tar`.
- Доступ к GitHub и внешним URL, которые используются выбранными модулями.

### Для управления RemnaNode

- Установленный RemnaNode в `/opt/remnanode`.
- Файл Compose: `/opt/remnanode/docker-compose.yml`.
- Для перенаправления HTTP: `/opt/remnanode/nginx.conf`, запущенный сервис
  `remnawave-nginx` и UFW.
- Docker с Compose plugin (`docker compose`).
- Для агента RemnaNode: `/opt/remnawave-node-agent`.
- Для системных операций: `systemd`, `apt-get`, `cron`.

Не все зависимости нужны одновременно: RemnaSuper проверяет необходимые
команды перед запуском соответствующего действия. Docker с Compose plugin
нужен для действий с RemnaNode и контейнерными интеграциями; `systemd` — для
Tor, Psiphon, fail2ban и аварийного восстановления парной диагностики.

## Установка

### Быстрая установка

Команда скачивает актуальную ветку `main`, устанавливает RemnaSuper в
`/opt/RemnaSuper`, создаёт ссылку `/usr/local/bin/rs` и запускает меню:

```bash
curl -fsSL https://raw.githubusercontent.com/SP1K33/RemnaSuper/main/install.sh \
  | sudo bash && sudo rs
```

После установки запуск из любой директории:

```bash
sudo rs
```

### Установка отдельными шагами

Если нужно сначала посмотреть установщик, используйте раздельный запуск:

```bash
curl -fsSL https://raw.githubusercontent.com/SP1K33/RemnaSuper/main/install.sh \
  -o /tmp/remnasuper-install.sh
sudo bash /tmp/remnasuper-install.sh
sudo rs
```

Установщик проверяет обязательные файлы архива, сохраняет нестандартный объект
по пути `/opt/RemnaSuper` с суффиксом `.legacy.*`, если он не является
каталогом, устанавливает приложение в `/opt/RemnaSuper`, создаёт ссылку
`/usr/local/bin/rs` и копирует `install.sh` и `README.md`, если они есть в
архиве.

### Установка из другой ветки

И установщик, и автообновление используют ветку из переменной
`REMNASUPER_BRANCH`:

```bash
curl -fsSL https://raw.githubusercontent.com/SP1K33/RemnaSuper/main/install.sh \
  | sudo REMNASUPER_BRANCH=dev bash
sudo REMNASUPER_BRANCH=dev rs
```

Передавайте переменную и при последующем запуске, чтобы автообновление
продолжало проверять ту же ветку. Без неё используется `main`.

## Запуск

RemnaSuper должна запускаться от `root`:

```bash
sudo rs
```

Для запуска без проверки обновлений:

```bash
sudo REMNASUPER_SKIP_UPDATE=1 rs
```

Значение `REMNASUPER_SKIP_UPDATE=1` отключает только проверку обновлений
RemnaSuper. Действия самого меню по-прежнему могут менять систему.

## Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `REMNASUPER_BRANCH` | `main` | Ветка GitHub для установщика и автообновления. Указывайте её при установке и каждом запуске `rs`, если используете другую ветку. |
| `REMNASUPER_SKIP_UPDATE` | `0` | При значении `1` пропускает проверку обновлений на GitHub для текущего запуска. |
| `REMNASUPER_DIAG_PORT` | `55443` | TCP-порт управляющего канала парной диагностики. Должен быть одинаковым на обеих VPS и находиться в диапазоне `1024–65535`. |

### Переход на вход по SSH-ключу

Пункт 2 рассчитан на OpenSSH со службой `ssh.service`, стандартным
`/etc/ssh/sshd_config` и файлом `~/.ssh/authorized_keys`. Укажите пользователя SSH,
доступный с компьютера адрес сервера и порт. Задайте имя новой папки внутри
`~/.ssh`, например `vps-berlin`, или нажмите Enter, чтобы использовать имя
на основе адреса сервера. Оставьте текущий сеанс открытым и выполните показанный
блок в PowerShell или Linux с установленным клиентом OpenSSH. Блок скачает
закрытый ключ по SCP в выбранную папку и проверит новое подключение с этим ключом.

Перед выдачей ключа RemnaSuper сохранит резервную копию `sshd_config`. После
проверки программа удалит временную копию закрытого ключа и перечитает
настройки SSH. Вход по паролю и интерактивные запросы аутентификации будут отключены для всех
учётных записей. Если проверка не завершится за пять минут, программа отменит
действие и удалит добавленный открытый ключ. Команда для следующих
подключений отображается вместе с командами скачивания.

## Сетевые интеграции

### ss-zapret2

Меню ss-zapret2 устанавливает и обновляет репозиторий
`vernette/ss-zapret2` в `/opt/ss-zapret2`, создаёт защищённый `.env` и
запускает Docker-контейнер `zapret2-proxy`.

Доступны следующие операции:

- установка и проверка локального SOCKS5;
- интерактивный поиск стратегии через `blockcheck2`;
- автоматическая запись найденных параметров в `NFQWS2_OPT`;
- просмотр текущей стратегии;
- ручное редактирование стратегии с проверкой и резервной копией;
- автоматический откат предыдущей конфигурации, если новая стратегия не
  запускается;
- полное удаление контейнера, образа, настроек и outbound.

По умолчанию SOCKS5 создаётся на `127.0.0.1:1080`, Shadowsocks-сервис
использует порт `8388`, а готовый outbound сохраняется в:

```text
/opt/ss-zapret2/xray-outbound.json
```

Его тег: `zapret`.

Для работы локального прокси из контейнера RemnaNode нода должна использовать
`network_mode: host`. Установка проверяет это требование и останавливается,
если оно не выполнено.

### Tor

Меню Tor:

- устанавливает Tor и необходимые системные пакеты;
- настраивает SOCKS5 только на `127.0.0.1:9050`;
- включает ControlPort только на `127.0.0.1:9051` с cookie-аутентификацией;
- проверяет выходной IP через Tor;
- создаёт JSON outbound для Xray;
- отправляет `SIGNAL NEWNYM` для запроса новой цепочки;
- удаляет только настройки и пакеты, которыми управляла RemnaSuper.

Outbound сохраняется в:

```text
/opt/remnasuper-tor/xray-outbound.json
```

Его тег: `tor`.

Важно:

- RemnaNode должна работать с `network_mode: host`, чтобы контейнер видел
  SOCKS5 на localhost.
- Этот outbound рассчитан на TCP-трафик. UDP через SOCKS5 Tor не
  поддерживается.
- `NEWNYM` не гарантирует новый IP при каждом запросе: Tor может выбрать тот
  же выходной узел.

### Psiphon

Psiphon устанавливается через актуальный установщик проекта
`Chara-Freedom/vps-psiphon` с флагом `--no-http`. В результате используются
Docker, systemd-сервис и watchdog, а наружу публикуется только SOCKS5 на
приватном адресе хоста.

Меню поддерживает:

- установку, переустановку и полное удаление выбранного подключения;
- несколько одновременных подключений на одной VPS: для каждого создаются отдельные
  контейнер, сервис systemd, watchdog, настройки, SOCKS5-порт и Xray outbound;
- выбор экземпляра для просмотра состояния, ротации, изменения регионов, проверки
  скорости и просмотра логов;
- просмотр состояния контейнера, systemd, watchdog, региона и выходного IP;
- ротацию туннеля;
- выбор фиксированного региона или `auto`;
- настройку пула регионов для последовательной ротации;
- настройку допустимых стран для watchdog;
- тест скорости;
- просмотр логов клиента и watchdog;
- генерацию актуального Xray outbound.

Первый outbound сохраняется в:

```text
/opt/vps-psiphon/xray-outbound.json
```

Его тег: `psiphon-out`.

Подключения устанавливаются через пункт **Добавить подключение**; установщик
поддерживает номера 1–99. Для дополнительных экземпляров используется тег вида
`psiphon-out-2` и далее, а файлы сохраняются в `/opt/vps-psiphon-N/`. После установки
добавьте outbound каждого нужного подключения в конфигурацию Xray и настройте
маршрутизацию на его тег. Удаление из меню затрагивает только выбранный экземпляр.

Как и Tor, Psiphon-outbound предназначен для TCP-трафика. Ротация или смена
региона может прервать текущие соединения примерно на 45 секунд. Проверка
скорости использует upstream-команду Psiphon и создаёт дополнительный сетевой
трафик; его объём зависит от текущей реализации upstream.

## Geofiles

В меню **Geofiles** доступны два источника:

- `Loyalsoldier/v2ray-rules-dat`;
- `Davoyan/xray-routing`.

Для каждого источника скачиваются `geosite.dat` и `geoip.dat`, файлы
сохраняются в `/opt/remnanode/geofiles` и подключаются в контейнер RemnaNode
через volumes:

```text
/usr/local/bin/<provider>-geosite.dat
/usr/local/bin/<provider>-geoip.dat
```

После установки для каждого файла создаётся безопасное ежедневное обновление
через cron в `00:00`. Новый файл скачивается во временный путь, проверяется на
непустое содержимое и только затем заменяет текущий. При ошибке существующий
файл сохраняется.

Резервные копии конфигурационных файлов RemnaSuper хранит в
`/opt/RemnaSuper/backups`. Здесь сохраняются копии `docker-compose.yml`,
`nginx.conf`, `torrc` и конфигурации ss-zapret2, в том числе для отката.
Имена единообразны: исходное имя файла, суффикс `.bak.`, дата и время
создания, затем уникальный идентификатор. Например:

```text
/opt/RemnaSuper/backups/docker-compose.yml.bak.YYYY-MM-DD_HHMMSS.XXXXXX
```

Перед изменением `docker-compose.yml` создаётся такая резервная копия.

При удалении набора RemnaSuper удаляет его файлы, volumes и связанные задания
cron.

## Логи и диагностика

### Парная диагностика двух VPS

Запустите актуальную RemnaSuper на обеих VPS: `sudo rs`. На VPS A и VPS B
выберите пункт **25**: перед вводом адреса программа покажет локальные IP
интерфейсов этой VPS (при NAT внешний адрес может отличаться). Укажите IP другой
VPS. В меню каждой VPS подтвердите запуск пункта 25. На A выберите «Создать парную
сессию» и один готовый профиль: программа покажет параметры нагрузки, ID сессии
и случайный одноразовый секрет без дополнительного запроса «ДА». На B выберите
«Присоединиться» и введите ID и секрет (секрет вводится без эха); параметры
нагрузки будут показаны перед началом тестов. Процессы на обеих VPS должны работать
одновременно. Управляющий TCP-порт A по умолчанию — `55443`. Если он занят,
задайте одинаковое значение переменной `REMNASUPER_DIAG_PORT` на обеих VPS
перед запуском `rs`, например `sudo REMNASUPER_DIAG_PORT=55444 rs`.
Не передавайте секрет через
публичный чат. Для отмены нажмите `Ctrl+C` на любой VPS.

Перед запуском пункт предлагает установить недостающие `python3`, `iperf3`,
`ufw`, `iproute2`, `iputils-ping`, `iputils-tracepath`, `mtr-tiny`, `sysstat` и
`curl` через `apt-get` после **отдельного** подтверждения. Установка пакетов —
постоянное изменение системы. Требуются работающий systemd и активный UFW с
входящей политикой `deny`; RemnaSuper не включает UFW, не меняет его глобальную
политику и не добавляет SSH-правила. Если UFW выключен, настройте его вручную
с сохранением доступа к SSH и RemnaNode и повторите запуск. Cloud firewall,
nftables и правила Docker могут дополнительно блокировать трафик; программа не
отключает их.

После выбора профиля дополнительные параметры не запрашиваются:

| Профиль | Ориентир времени | Файл в каждом направлении | TCP-прогон | Стабильность в каждом направлении | UDP-датаграммы |
| --- | ---: | ---: | ---: | ---: | ---: |
| Быстрый | около 5 минут | 64 MiB | 6 с | 20 с | 2 с на размер |
| Средний | около 15 минут | 1 GiB | 15 с | 120 с | 3 с на размер |
| Полный | около 30 минут | 1 GiB | 30 с и повтор 1 потока | 420 с | 5 с на размер |

Быстрый профиль использует 30 базовых ICMP-проб на направление, 100 echo-запросов
на размер, до 200 UDP-датаграмм/с, одну ступень UDP iperf3 (5% измеренного TCP,
6 с), RTT под нагрузкой 10 с и двусторонний тест 10 с. MTU/маршрут в нём
пропускаются. Средний профиль использует 100 проб, 500 echo-запросов, до
500 UDP-датаграмм/с, три ступени UDP iperf3 (5/25/50%, по 6 с), RTT под
нагрузкой 15 с и двусторонний тест 15 с. Полный профиль использует 100 проб,
1000 echo-запросов, до 1000 UDP-датаграмм/с, три ступени UDP iperf3 по 10 с,
RTT под нагрузкой 20 с и двусторонний тест 20 с. Средний и полный профили
проверяют MTU/маршрут. Все направленные проверки выполняются отдельно A→B и B→A.

Все профили используют цель TCP 100 Mbps только для оценки и предел нагрузки
150 Mbps. Средний и полный профили создают реальный несжатый файл **1 GiB на
каждом отправителе**, передают его в обоих направлениях и сверяют длину и
SHA-256. Минимум файлового трафика — **2 GiB**; TCP/UDP-прогоны добавляют
трафик. Быстрый профиль использует меньший файл и отмечает оценку как
предварительную. Перед стартом программа показывает ориентир дополнительного
трафика. Время профиля приблизительное: общий срок не обрывает проверки, поэтому
на медленном канале сессия может занять больше времени. Файл помечается `PARTIAL`,
если передача прервана или завершилась с ошибкой; отдельные сетевые операции
сохраняют тайм-ауты для обнаружения зависаний и потери связи. Ограничение скорости
не определяет физический предел канала. Тест
может влиять на VPN-пользователей и тарификацию провайдера.

Агент выполняет раздельные A→B и B→A прогоны TCP с 1, 4 и 8 потоками,
файловую передачу, ограниченные echo и UDP-датаграммы, UDP через iperf3,
ICMP/TCP RTT, RTT под нагрузкой, длительный TCP-прогон, tracepath/mtr при
доступности и отдельный двусторонний тест. Неизмеренное значение остаётся
`null`/`SKIPPED`/`FAILED`, а усечённый файл — `PARTIAL`. RTT получен по
локальному монотонному времени; односторонняя задержка без синхронизации часов
не вычисляется. Счётчики интерфейса и ядра могут включать трафик других
пользователей.

Управляющий канал использует одноразовый 256-битный секрет, взаимное
challenge-response и HMAC-SHA256 с последовательными номерами. Секрет по сети
не передаётся. **HMAC не шифрует метаданные**: запускайте диагностику только
между доверенными VPS и не включайте секреты в имена или параметры. Тестовый
TCP echo/файловый поток проверяет HMAC при подключении, UDP проверяет HMAC
каждой датаграммы. iperf3 защищён адресным правилом UFW. Управляющий порт
открывается на A только для IP B на время сессии; тестовые порты выбираются в
`55000–55999` и открываются **только на текущем получателе**. Для UDP iperf3
временно открываются TCP и UDP на одном порту. После каждого этапа его
правила и слушатели закрываются. Если порт занят, другие сервисы не
останавливаются.

До открытия первого порта агент создаёт журнал владения с правами `0600` и
systemd watchdog с boot recovery. При потере heartbeat, `SIGKILL` или
перезагрузке он сверяет журнал и удаляет только собственные правила
UFW и процессы. При невозможности доказать владение правилом его не удаляют;
отчёт получает `CLEANUP_INCOMPLETE` и путь журнала для администратора.
Установка и обновление RemnaSuper откладываются, пока есть активный или
неочищенный журнал. Парные сеансы на одной VPS блокируются через `flock`.

На каждой VPS отчёты сохраняются в
`/var/log/remnasuper/network-diagnostics/<UTC>-<session-id>/result.json` и
`summary.md`; там же остаются сырые JSON iperf3. Отчёты не содержат секрет
сопряжения. Оценки A→B, B→A и общий балл 1–10 рассчитаны для профиля
«VPN/VPS-мост» по весам и порогам из `report.py`. Общий балл равен худшему
направлению. При неполном покрытии, отсутствии полного файла/UDP или пределе
скорости не выше цели оценка помечается предварительной. Тест прямого IP→IP
не является точным измерением VLESS, REALITY, WireGuard или Xray.

Ручную приёмку выполняйте только на двух отдельных одноразовых Debian/Ubuntu
VPS или VM: проверьте неверный секрет и IP, занятый порт, отключённый UFW,
прерывание `Ctrl+C`, разрыв управляющего канала, `SIGKILL` агента и reboot во
время прогона. После каждого сценария проверьте собственные правила UFW,
слушатели, временные файлы, состояние systemd recovery и оба отчёта. На
продуктивных VPS нагрузочные проверки проводите только с согласия
администратора.

### Логи RemnaNode

Пункт **Исправить логи RemnaNode**:

1. создаёт `/var/log/remnanode/access.log` и `error.log`;
2. подключает каталог к сервису `remnanode`;
3. перезапускает RemnaNode и node-agent;
4. проверяет, начал ли заполняться `access.log`;
5. предлагает профиль `logrotate`.

Доступны профили ротации:

- малая нода: ежедневно, хранить 7 дней;
- средняя нода: ежедневно, хранить 3 дня;
- высокая нагрузка: ротация `access.log` после 100 МБ, хранить 5 архивов;
- ручное редактирование конфига через `nano`.

Конфигурация хранится в:

```text
/etc/logrotate.d/remnanode
```

### Встроенная проверка доступности

Проверка выполняется без скачивания сторонних скриптов и показывает для
Discord, YouTube, Telegram и Instagram:

- DNS IPv4 и IPv6;
- ICMP-пинг и потери пакетов;
- HTTP-код и версию HTTP;
- результат проверки TLS-сертификата;
- локальный и удалённый IP/порт;
- конечный URL после перенаправлений;
- задержки DNS, TCP, TLS, TTFB и общее время;
- объём полученных данных и скорость загрузки.

Проверка намеренно игнорирует переменные HTTP-прокси и выполняет запросы
напрямую. Отсутствие ICMP-ответа само по себе не означает, что HTTPS
недоступен.

### Node Accelerator

RemnaSuper запускает upstream-установщик
[Node Accelerator](https://github.com/jestivald/node-accelerator) и не
дублирует его код.

Доступны модули:

- `optimize`: XanMod, BBRv3, sysctl, лимиты, RPS/RFS/XPS, swap и настройка
  сетевого интерфейса;
- `protect`: nftables, защита от сканирования и флуда, CrowdSec и
  автоопределение порта node-agent;
- `diagnose`: read-only проверка ядра, BBR, sysctl, лимитов, conntrack, NIC,
  firewall, CrowdSec, портов и RemnaNode;
- `persist`: установка/обновление read-only CLI `na-diagnose` и `na-report`.

В подменю также доступны установка всех модулей и штатный откат `optimize`,
`protect` или обоих модулей. При откате `optimize` ядро XanMod остаётся
установленным, а при откате `protect` остаётся CrowdSec.

Модули `optimize` и `protect` меняют системные настройки. После успешной
установки `optimize` или всех модулей VPS автоматически перезагружается;
текущие подключения прервутся. Перед применением firewall проверьте порты и
whitelist, чтобы не потерять SSH-доступ.

## Автообновление

При запуске RemnaSuper проверяет наличие обновления в выбранной ветке GitHub.
Если обновление доступно, программа скачивает архив, заменяет файлы в
`/opt/RemnaSuper` и автоматически перезапускает `rs`.

Если GitHub временно недоступен, RemnaSuper сообщает об ошибке проверки и
продолжает запуск. Проверку можно отключить на один запуск:

```bash
sudo REMNASUPER_SKIP_UPDATE=1 rs
```

Автообновление изменяет только файлы самой RemnaSuper. Конфигурации
RemnaNode, Docker, Tor, Psiphon и ss-zapret2 находятся за пределами каталога
`/opt/RemnaSuper` и не заменяются механизмом обновления.

```bash
set -e
while IFS= read -r -d '' file; do
    case "$file" in
        RemnaSuper|*.sh) bash -n "$file" ;;
    esac
done < <(git ls-files -z)
```

Если установлен ShellCheck:

```bash
find lib -type f -name '*.sh' -print0 \
  | xargs -0 shellcheck RemnaSuper install.sh
```

Полный запуск `sudo ./RemnaSuper` может проверить и установить обновление, а
пункты меню изменяют реальный сервер. Для ручной проверки интерфейса задавайте
`REMNASUPER_SKIP_UPDATE=1`. Интеграционные проверки системных действий
проводите на одноразовой Debian/Ubuntu VM или тестовом сервере.

## Безопасность и ограничения

- Запускайте RemnaSuper только на сервере, которым вы управляете.
- Перед изменением Compose сохраняйте и просматривайте созданный `.bak`.
- Установка `remnawave-reverse-proxy`, Node Accelerator, `Node Precheck`,
  `ipregion`, `IP Check Place`, `bench.sh`, Psiphon и ss-zapret2 скачивает код из
  внешних репозиториев или URL. Ознакомьтесь с upstream-проектами перед
  запуском.
- `Node Precheck` обращается к внешним сервисам и передаёт им публичный IP для
  проверок; тест скорости может передать до 25 МБ и скачать до 190 МБ. Тест
  записи на диск выключен по умолчанию.
- `Node Accelerator` может изменить ядро, sysctl, firewall, лимиты и
  сетевые параметры.
- Установка `fail2ban` записывает `/etc/fail2ban/jail.d/local.conf` с
  параметрами SSH: 4 попытки за 10 минут и бан на 1 час.
- Перезапуск RemnaNode обычно прерывает подключения примерно на 5–10 секунд.
- Ротация или смена региона Psiphon может прервать соединения примерно на
  45 секунд.
- Tor и Psiphon outbound используют локальный SOCKS5 и предназначены только
  для TCP-трафика; UDP через эти outbound не поддерживается.
- Для локальных конфигураций с секретами применяются ограниченные права,
  например `/opt/ss-zapret2/.env` имеет режим `0600`.
- Не запускайте `lib/*.sh` напрямую и не используйте рабочий сервер для
  экспериментов с сетевыми стратегиями или firewall.
