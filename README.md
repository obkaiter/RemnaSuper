# RemnaSuper

Интерактивное меню для обслуживания RemnaNode: логи, logrotate, geofiles, шейпинг трафика, перезапуск сервисов и вспомогательные команды.

Встроенная диагностика доступности проверяет Discord, YouTube, Telegram и Instagram без сторонних скриптов: показывает DNS-адреса, ICMP-пинг, HTTP-статус, сетевой маршрут запроса и задержки DNS/TCP/TLS/TTFB.

## Установка и запуск

Одна команда скачает актуальную версию из GitHub, установит файлы в `/opt/RemnaSuper`, создаст команду `/usr/local/bin/rs` и сразу запустит меню:

```bash
curl -fsSL https://raw.githubusercontent.com/SP1K33/RemnaSuper/main/install.sh | sudo bash && sudo rs
```

После установки запуск доступен из любой директории:

```bash
sudo rs
```

## Версия и автообновление

Текущая версия хранится в файле `VERSION`. При каждом запуске RemnaSuper проверяет `VERSION` в репозитории `https://github.com/SP1K33/RemnaSuper`. Если в GitHub версия новее, скрипт автоматически обновляет файлы в `/opt/RemnaSuper`, сообщает об этом и перезапускается.

Для временного отключения проверки:

```bash
sudo REMNASUPER_SKIP_UPDATE=1 rs
```

## Шейпер трафика

Пункт «Управление шейпером трафика» устанавливает локальный eBPF/EDT-движок и systemd-сервис `remnasuper-traffic-shaper.service`. Поддерживаются до 32 независимых правил и до 32 TCP/UDP-портов в каждом правиле:

- постоянный лимит Download/Upload на каждый внешний IP клиента;
- burst-квота с временным штрафом;
- общий канал, разделяемый всеми клиентами правила;
- точный IPv4/IPv6 whitelist;
- статистика трафика, сбросов и активных штрафов.

Скорости в меню задаются в Мбит/с, burst-квота — в МиБ. Настройки хранятся в `/etc/remnasuper/traffic-shaper` и автоматически восстанавливаются после перезагрузки.

Требования: Debian/Ubuntu, ядро Linux 5.4+, `systemd` и доступные в репозитории пакеты `clang`, `libbpf-dev`, `bpftool`, `iproute2`. RemnaSuper установит их при первом включении шейпера.

### Особенности и совместимость

RemnaNode обычно работает с `network_mode: host`, поэтому шейпер видит внешний адрес VPN-клиента, а не пользователя панели Remnawave. Несколько клиентов за одним NAT разделяют один per-IP лимит.

Для Download используется EDT, которому требуется корневая очередь `fq`. Пока сервис активен, RemnaSuper заменяет корневую очередь выбранного интерфейса на собственную `fq` с отдельным handle. При штатной остановке она удаляется только если всё ещё принадлежит RemnaSuper. Параметры BBR, RPS/RFS/XPS и nftables из Node Accelerator не удаляются. После действий Node Accelerator, способных изменить сетевые настройки, активный шейпер автоматически перезапускается и повторно применяет `fq`.

Upload ограничивается на ingress небольшим token-bucket и сбросом лишних пакетов: TCP и QUIC автоматически снижают скорость, но для насыщенного UDP это может означать заметную потерю пакетов.

Правило с портом `0` перехватывает весь TCP/UDP-трафик интерфейса, включая SSH, панель, node-agent и системные соединения. Безопаснее указывать только публичные входящие порты Xray; при настройке wildcard RemnaSuper предлагает добавить текущий SSH-IP в whitelist.

Остановка через меню сохраняет правила. Полное удаление удаляет сервис, BPF-карты, правила и whitelist.
