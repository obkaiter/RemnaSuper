# RemnaSuper

RemnaSuper — интерактивная Bash-утилита для администрирования RemnaNode и
HAProxy-релеев на Debian и Ubuntu. Через меню можно подготовить VPS, настроить
RemnaNode, управлять сетевыми интеграциями, смотреть логи и проверять связь.

## Требования

- Debian или Ubuntu, Bash, GNU-утилиты, APT и systemd.
- Права `root` и интерактивный терминал. Для запуска удалённой командой
  выделите терминал, например `ssh -t admin@server 'sudo rs'`.
- `curl` и `tar` для установки и автообновления. С GitHub и другими внешними
  источниками должен быть доступ по сети со стороны сервера.
- Для действий с нодой нужны Docker с плагином Compose (`docker compose`),
  установленная RemnaNode и `/opt/remnanode/docker-compose.yml` с сервисом
  `remnanode`. Агент, если установлен, ожидается в
  `/opt/remnawave-node-agent`. [RemnaNode](https://github.com/remnawave/node)

HAProxy-релей, первоначальная подготовка VPS и сетевые проверки доступны
отдельно от RemnaNode. Дополнительные зависимости указаны в описаниях действий.

## Установка и обновление

Для установки или обновления выполните одну команду. Она скачивает
установщик из ветки `main` на GitHub и запускает его с правами root.

```bash
curl -fsSL https://raw.githubusercontent.com/obkaiter/RemnaSuper/main/install.sh | sudo bash
```

Установщик скачивает архив по коммиту выбранной ветки, проверяет обязательные
файлы, устанавливает приложение в `/opt/RemnaSuper` и создаёт ссылку
`/usr/local/bin/rs`. Если по пути установки уже находится обычный файл или
символическая ссылка, установщик переносит его в `/opt/RemnaSuper.legacy.*`.
Для запуска RemnaSuper выполните `sudo rs`.

До показа меню RemnaSuper запрашивает `VERSION` выбранной ветки на GitHub.
Если удалённая версия новее, приложение скачивает архив по коммиту ветки
и проверяет, что версия архива не ниже объявленной. После установки
запускается обновлённый `/opt/RemnaSuper/RemnaSuper`. Если проверка недоступна,
открывается меню установленной версии. При ошибке замены файлов приложение
сообщает об ошибке и восстанавливает прежние файлы.
Обновление заменяет `RemnaSuper`, `VERSION`, каталог
`lib/`, код и unit сборщика HAProxy, а также `README.md` и `install.sh`, если
они есть в архиве. Конфигурация сборщика, SQLite, логи, выгрузки и резервные
копии сохраняются. Активный сборщик перезапускается при изменении его кода
или unit. Системные скрипты интеграций запускаются через соответствующие пункты
меню.

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `REMNASUPER_BRANCH` | `main` | Ветка, из которой установщик скачивает архив и в которой `rs` проверяет обновления. При установке из другой ветки передавайте то же значение установщику и при каждом запуске `rs`. |
| `REMNASUPER_SKIP_UPDATE` | `0` | Значение `1` пропускает проверку и установку обновления в текущем сеансе. |

```bash
sudo REMNASUPER_SKIP_UPDATE=1 rs
```

При переходе с версии с парной диагностикой двух VPS сначала завершите
активные сеансы диагностики и дождитесь очистки их ресурсов. Затем выполните
команду установки выше. Старый автообновлятор требует файлы парной диагностики,
удалённые начиная с 6.28.

## Первоначальная настройка

| Пункт | Что делает |
| --- | --- |
| **Node Precheck** | Запускает диагностику новой VPS. [Подробности](#node-precheck) |
| **Сгенерировать ssh-ключ и отключить вход по паролю** | Создаёт ключ Ed25519 и меняет настройки OpenSSH после проверки входа. [Подробности](#переход-на-вход-по-ssh-ключу) |
| **apt update && apt upgrade** | Обновляет пакеты, устанавливает `cron`, `mc` и `wget`, затем автоматически перезагружает VPS. |
| **Отключить IPv6** | Отключает IPv6 через sysctl сразу и после перезагрузки. IPv6-подключения, включая SSH, могут прерваться. |
| **Установить fail2ban** | Записывает `/etc/fail2ban/jail.d/local.conf`, включает защиту SSH и автозапуск. Четыре неудачные попытки за десять минут приводят к блокировке на час. |
| **Установить rkn-guard** | Запускает внешний установщик от root и настраивает фильтрацию сканеров через `iptables` и `ipset`, логирование и службы systemd. Установщик может предложить автообновление списков. [rkn-guard](https://github.com/Flecksis/rkn-guard) |
| **Установить remnawave-reverse-proxy** | Скачивает и запускает `install_remnawave.sh` от root. [remnawave-reverse-proxy](https://github.com/eGamesAPI/remnawave-reverse-proxy) |
| **Сменить порт взаимодействия с панелью** | Меняет `NODE_PORT` в Compose, переносит разрешающее правило UFW и перезапускает ноду. Укажите новый порт в настройках ноды на панели после изменения. |
| **Подключить сертификаты в ноду** | Находит домен в volumes сервиса `remnawave-nginx` и подключает `fullchain.pem` и `privkey.pem` из `/etc/letsencrypt/live/<домен>/` в `/etc/nginx/ssl/<домен>/` внутри `remnanode` в режиме только для чтения. Нода перезапускается. |
| **Исправить логи (access.log, xray.out.log)** | Подключает каталог логов и предлагает профиль ротации. [Подробности](#логи-remnanode) |
| **Заглушка: TLS 1.2, TLS 1.3 и HSTS** | Добавляет HSTS на год с `includeSubDomains` в TLS-блоки с доменным `server_name` в `/opt/remnanode/nginx.conf`. Проверяет конфигурацию в работающем `remnawave-nginx` и перезапускает ноду. |
| **Установка/удаление geofiles** | Управляет файлами маршрутизации, заданиями cron и volumes. [Подробности](#geofiles) |
| **Ограничить исходящий SMTP** | Управляет правилами nftables и показывает правило Xray. [Подробности](#ограничение-исходящего-smtp) |
| **Управление Node Accelerator** | Запускает установку, диагностику и откат модулей. [Подробности](#node-accelerator) |
| **Удалить IPv6 из ufw** | Удаляет пользовательские IPv6-правила из `/etc/ufw/user6.rules` после резервного копирования. При активном UFW с поддержкой IPv6 применяет изменения сразу. Доступ по IPv6 может измениться. |

Для смены порта в `environment` сервиса `remnanode` нужна одна запись
`NODE_PORT=<порт>` и одно входящее разрешающее правило UFW для этого порта
с указанным источником. RemnaSuper сохраняет протокол и источник правила.
Пустой ввод выбирает свободный порт из диапазона 49152–65535.

### Переход на вход по SSH-ключу

Нужен работающий `ssh.service` со стандартным путём `/etc/ssh/sshd_config`.
Укажите пользователя, адрес и порт сервера, затем выберите имя новой папки
для ключа в локальном `~/.ssh`. На своём компьютере выполните показанные
команды для PowerShell или Bash. Они скачивают закрытый ключ по SCP и
проверяют новое подключение этим ключом. Оставьте исходный SSH-сеанс
открытым до завершения.

Программа добавляет публичный ключ в `~/.ssh/authorized_keys` выбранного
пользователя и сохраняет резервную копию `sshd_config`. После успешной проверки
она подключает `/etc/ssh/remnasuper-key-only.conf` и перечитывает настройки
`ssh.service`. Парольная и интерактивная аутентификация отключаются глобально.
Временная серверная копия закрытого ключа удаляется. Если за пять минут
проверка не состоялась, действие отменяется, а добавленный публичный ключ
удаляется.

### Ограничение исходящего SMTP

Подменю показывает состояние правил и автозапуска. **Включить ограничение**
при необходимости устанавливает `nftables` через APT и включает службу
`remnasuper-smtp-egress.service`. Служба применяет таблицу
`inet remnasuper_smtp` сразу и при загрузке системы.

- Исходящий TCP/25 блокируется.
- TCP/465 и TCP/587 делят лимит новых соединений — пять попыток в час с
  запасом до пяти попыток подряд. Запас пополняется на одну попытку за
  12 минут. Установленные соединения на этих портах продолжают работать.
  Одно соединение может передать несколько писем.
- Лимит общий для IPv4, IPv6, хоста и исходящего трафика через мосты Docker.
  Повторное включение действующих правил сохраняет счётчики и запас попыток.

**Показать правило Xray** выводит JSON для ручного добавления в
`routing.rules` перед разрешающими правилами. Оно направляет TCP/25 в outbound
`block` с протоколом `blackhole`. Если у этого outbound другой тег, укажите его
в `outboundTag`. При переходе с полной блокировки из 6.23 снова включите
ограничение и замените старое правило в профиле Xray, если оно блокирует все
три порта.

После сброса таблиц nftables выберите **Включить ограничение**, чтобы вернуть
правила. **Выключить ограничение** останавливает службу, отключает автозапуск
и удаляет её таблицу. Правила Xray редактируются в профиле ноды.

```bash
sudo systemctl status remnasuper-smtp-egress.service
sudo nft list table inet remnasuper_smtp
```

### Node Accelerator

Меню запускает внешний установщик от root. Модуль `optimize` настраивает
ядро XanMod, BBRv3, sysctl, лимиты, swap и сетевой интерфейс. `protect`
настраивает nftables, CrowdSec и защиту от сканирования и флуда. `diagnose`
проверяет сервер, а `persist` устанавливает команды `na-diagnose` и
`na-report`. [Node Accelerator](https://github.com/jestivald/node-accelerator)

После успешной установки оптимизатора или всех модулей VPS автоматически
перезагружается. Перед установкой защиты проверьте порты и список разрешённых
адресов для SSH. Меню поддерживает штатный откат оптимизации и защиты по
отдельности или вместе. При откате ядро XanMod и CrowdSec остаются
установленными.

## HAProxy-релей

В меню **Настройка релея** доступны три раздела.

| Раздел | Действия |
| --- | --- |
| **Первоначальная настройка** | Установка, запуск, остановка и перезапуск HAProxy, установка сайта-заглушки, удаление HAProxy и сборщика. |
| **Обслуживание HAProxy** | Маршруты SNI, ограничение скорости, состояние службы, проверка Stats Socket, конфигурация и журнал HAProxy, резервная копия SQLite, экспорт CSV и отключение рассылки аварийных логов в терминалы. |
| **Просмотр статистики** | Отчёты за сегодня, вчера, выбранный месяц, по дням месяца и за весь сохранённый период. Доступны отчёт по Backend, список Backend, последние измерения и состояние сборщика. |

### Установка и маршруты SNI

Для установки выберите **Настройка релея → Первоначальная настройка →
Установить HAProxy**. Пакеты берутся из системных репозиториев. Сборщику
требуется Python 3.9 или новее с `sqlite3` и `zoneinfo`. Установка сохраняет
существующий конфиг и базу, настраивает Unix Stats Socket в секции `global`
и предлагает включить `option contstats` в `defaults`. При отсутствии
`/etc/haproxy/haproxy.cfg` APT восстанавливает штатный файл из пакета.

Пункт **Обслуживание HAProxy → Управление подключениями → Добавить
подключение** связывает SNI с одноимённым доменом выходной ноды. DNS имени
должен вести на выходную ноду. Порт назначения по умолчанию — `443`, можно
указать любой порт от `1` до `65535`. В штатной конфигурации без секций
`frontend`, `listen` и `backend` первый маршрут создаёт входной IPv4-слушатель
TCP/443.

При ручной конфигурации новый маршрут добавляется в `frontend bitwire_entry`.
Если распознан список разрешённых SNI, домен добавляется и туда. Чтобы
удалить маршрут, выберите его в списке и нажмите **Удалить подключение**.
При удалении прямого маршрута домен убирается из распознанного ACL, если
в этой секции больше нет маршрутов для него. Секция `backend` удаляется,
если она соответствует шаблону RemnaSuper и на неё больше нет ссылок.
Удаление доступно и после того, как перестал разрешаться домен назначения.

Перед применением изменений RemnaSuper сохраняет резервную копию и проверяет
конфигурацию. Работающий HAProxy перечитывает её через `reload`, остановленная
служба запускается.

### Сайт-заглушка

Пункт **Настройка релея → Первоначальная настройка → Установить
сайт-заглушку** добавляет маршрут SNI к nginx через Unix-сокет с учётом
`chroot` HAProxy. Файлы сайта размещаются в `/var/www/remnasuper-relay`.
Для HTTPS включены TLS 1.2 и TLS 1.3, TLS session tickets отключены.

Домену нужна запись `A`, указывающая на IPv4 релея. Для подключённого
сертификата и пары в `/etc/letsencrypt/live/<домен>/` RemnaSuper проверяет
имя, срок, цепочку доверия и соответствие закрытому ключу. Если пригодной
пары нет, RemnaSuper скачивает закреплённую версию `acme.sh`, проверяет
SHA-256 и выпускает сертификат Let's Encrypt через HTTP-01. Для выпуска и
продления TCP/80 должен быть доступен извне. Если у домена есть запись `AAAA`,
по ней также должна быть доступна проверка HTTP-01 на релейном сервере.
Cron запускает продление, а nginx перечитывает конфигурацию после обновления
сертификата. При повторной установке ранее созданный самоподписанный
сертификат заменяется рабочим.

### Лимит скорости

Пункт **Обслуживание HAProxy → Лимит скорости** требует HAProxy 2.7 или
новее и входной `frontend bitwire_entry`. Укажите целое число от 1 до
34 359 Мбит/с или удалите ограничение через меню. Все TCP-соединения с одного
исходного IP делят один лимит загрузки и отдельный лимит отдачи. Например,
значение `100` даёт до 100 Мбит/с в каждом направлении для одного IP, в том
числе если за этим IP несколько пользователей. Изменение действует для
новых соединений после перечитывания конфигурации.

### Как считается трафик

Сборщик `haproxy-traffic.service` по умолчанию каждые 60 секунд выполняет
`show stat` через Unix Stats Socket. Источник данных — итоговые строки
`BACKEND`, включая Backend в состоянии `DOWN`. Upload берётся из `bin`
(к Backend), Download — из `bout` (к клиенту).

Первый замер задаёт базу счётчиков. При смене процесса HAProxy, повторном
появлении Backend или уменьшении счётчика сборщик создаёт новую базу. История
сохраняется, но трафик между последним опросом старого процесса и первым
опросом нового может отсутствовать в отчёте. Долгие соединения могут
отражаться с задержкой без `option contstats`. Интервал относится ко дню его
окончания в часовом поясе отчёта (`Europe/Moscow` по умолчанию). Метки
времени хранятся в UTC. Срок хранения интервалов и событий по умолчанию —
365 дней.

Средняя скорость — суммарный Upload и Download в мегабитах, делённый на
длительность записанных интервалов в секундах. В общем итоге время
одновременных замеров разных Backend учитывается один раз. В списке Backend
и в состоянии сборщика показана скорость за последний интервал.

| Путь относительно `/opt/RemnaSuper/haproxy` | Назначение |
| --- | --- |
| `config/config.json` | Сокет, база, интервал опроса, часовой пояс, срок хранения и уровень логирования |
| `collector/` | Python-сборщик и команды отчётов |
| `database/traffic.sqlite3` | SQLite в режиме WAL |
| `logs/collector.log` | Журнал сборщика с ротацией |
| `run/admin.sock` | Stats Socket |
| `systemd/haproxy-traffic.service` | Unit, регистрируемый ссылкой из `/etc/systemd/system/` |
| `backups/`, `exports/` | Резервные копии конфигурации и SQLite, экспорт CSV за месяц |

Примеры просмотра и экспорта из SSH.

```bash
sudo python3 -B /opt/RemnaSuper/haproxy/collector/collector.py today
sudo python3 -B /opt/RemnaSuper/haproxy/collector/collector.py month 2026-11
sudo python3 -B /opt/RemnaSuper/haproxy/collector/collector.py backend exit_nl --month 2026-11
sudo python3 -B /opt/RemnaSuper/haproxy/collector/collector.py export --month 2026-11
```

Журнал HAProxy доступен в меню обслуживания и через
`journalctl -u haproxy.service`. В новых установках RemnaSuper корректирует
стандартные директивы `log /dev/log` без заданного минимального уровня:
`emerg` записывается с уровнем `alert`, поэтому при `MaxLevelWall=emerg`
journald не рассылает такие сообщения по терминалам. На существующем релейном
сервере настройка доступна через **Отключить рассылку аварийных логов HAProxy
в терминалы**.

**Удалить HAProxy и сборщик** останавливает службы и удаляет пакет через
`apt-get remove`. В меню можно сохранить историю или удалить каталог
сборщика вместе с SQLite, журналами, выгрузками и резервными копиями.
Директивы Stats Socket и `contstats`, добавленные модулем, убираются из
`haproxy.cfg`. Маршруты в конфигурации HAProxy сохраняются.

## Сетевые интеграции

Для ss-zapret2, Tor и Psiphon RemnaSuper готовит JSON outbound. Добавьте нужный
outbound в профиль Xray и направьте трафик на его тег правилами маршрутизации.

### Psiphon

Пункт **Управление Psiphon** скачивает внешний установщик и запускает его с
`--no-http`. Каждый экземпляр получает свой Docker-контейнер, службу
systemd, watchdog и SOCKS5 на приватном адресе хоста.
[vps-psiphon](https://github.com/Chara-Freedom/vps-psiphon)

Пункт **Добавить подключение** предлагает первый свободный номер от 1 до
99. Можно указать другой свободный номер. Для выбранного экземпляра
доступны состояние, ротация, фиксированный регион или `auto`,
последовательный пул регионов, список допустимых стран для watchdog, тест
скорости, логи и переустановка. Удаление затрагивает выбранный экземпляр.
Ротация или смена региона может прервать соединения примерно на 45 секунд.

Первый outbound хранится в `/opt/vps-psiphon/xray-outbound.json` с тегом
`psiphon-out`. Дополнительные экземпляры используют каталоги
`/opt/vps-psiphon-N/` и теги `psiphon-out-N`. Outbound рассчитан на TCP.

### Tor

Пункт **Управление Tor** устанавливает Tor, включает локальный SOCKS5 на
`127.0.0.1:9050` и ControlPort на `127.0.0.1:9051` с cookie-аутентификацией,
проверяет выходной IP и сохраняет TCP-outbound с тегом `tor` в
`/opt/remnasuper-tor/xray-outbound.json`. Контейнеру RemnaNode нужен
`network_mode: host` для доступа к SOCKS5 через localhost.

Действие **Быстро сменить выходной IP** запрашивает новую цепочку через
`NEWNYM`. Tor может повторно выбрать тот же выходной узел. Удаление
восстанавливает настройки, которыми управляла RemnaSuper, и удаляет
пакеты, установленные ею для Tor.

### WARP Native

Пункт **Управление warp** устанавливает и удаляет Cloudflare WARP через
WireGuard. Скрипты установки и удаления загружаются из ветки `main`
внешнего проекта, проходят проверку синтаксиса и ожидаемых строк, затем
запускаются от root. [WARP Native](https://github.com/distillium/warp-native)

Установщик настраивает интерфейс `warp`, службу `wg-quick@warp`, watchdog
через cron и kill-switch в nftables. Во время установки он временно меняет
DNS в `/etc/resolv.conf` и может перезаписать `/etc/resolv.conf.backup` и
`/etc/wireguard/warp.conf`. Kill-switch блокирует трафик Xray с меткой
`51888`, если он идёт мимо интерфейса `warp`. Маршрутизация Xray
настраивается отдельно в его профиле.

Из подменю можно посмотреть состояние службы, параметры WireGuard и адреса
интерфейса, запустить, остановить или перезапустить его, а также отдельно
включить или отключить автозапуск. При остановке или удалении активные
соединения через WARP прерываются. Удаление очищает файлы интеграции,
watchdog и таблицу nftables `warp_native`. Пакеты WireGuard удаляются при
отсутствии других обнаруженных интерфейсов и конфигураций WireGuard.

### ss-zapret2

Пункт **Управление ss-zapret2** устанавливает или обновляет проект в
`/opt/ss-zapret2`, создаёт `.env` с правами `0600` и запускает контейнер
`zapret2-proxy`. Установка проверяет `network_mode: host` у RemnaNode.
[ss-zapret2](https://github.com/vernette/ss-zapret2)

По умолчанию локальный SOCKS5 использует `127.0.0.1:1080`, а Shadowsocks —
порт `8388`. Outbound с тегом `zapret` сохраняется в
`/opt/ss-zapret2/xray-outbound.json`. При миграции с `/opt/ss-zapret`
RemnaSuper переносит настройки прокси, останавливает старый контейнер и
сохраняет его файлы. В меню доступны поиск параметров `NFQWS2_OPT` через
`blockcheck2` с автоматическим применением результата, просмотр и ручная
настройка стратегии с резервной копией и откатом при неудачном запуске,
а также удаление контейнера, образа и конфигурации.

## Geofiles

Откройте **Первоначальная настройка → Установка/удаление geofiles**. Можно
добавить или удалить один набор либо все сразу. Для загрузки нужны `wget`,
`crontab` и `flock`. Файлы сохраняются в `/opt/remnanode/geofiles` и
монтируются в `/usr/local/bin/` внутри контейнера `remnanode`.

| Набор | Имена файлов в контейнере |
| --- | --- |
| [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) | `loyalsoldier-geosite.dat`, `loyalsoldier-geoip.dat` |
| [Davoyan/xray-routing](https://github.com/Davoyan/xray-routing) | `xray-routing-geosite.dat`, `xray-routing-geoip.dat` |
| [Chocolate4U/Iran-v2ray-rules](https://github.com/Chocolate4U/Iran-v2ray-rules) | `security.dat`, `security-ip.dat` |

При наличии Compose RemnaSuper проверяет изменённый файл, сохраняет резервную
копию перед заменой и пересоздаёт контейнеры. Без Compose установка скачивает
файлы и настраивает cron. Задания root загружают новые версии ежедневно в
00:00 по времени cron. Замена происходит после проверки, что загруженный
временный файл непустой. После обновления через cron пересоздайте контейнер,
чтобы он увидел новые файлы.

Для Chocolate4U меню выводит правила, направляющие категории `malware`
и `phishing` в outbound `block` с протоколом `blackhole`. Правила
добавляются вручную в `routing.rules` перед разрешающими правилами.
Перед удалением любого набора уберите ссылки на его файлы из профиля Xray.
RemnaSuper удалит volumes, файлы и задания cron выбранного набора.

## Логи и диагностика

### Логи RemnaNode

Пункт **Исправить логи (access.log, xray.out.log)** создаёт `access.log` и
`error.log` в `/var/log/remnanode`, монтирует каталог в `remnanode` и
перезапускает ноду. Если присутствует каталог node-agent, скрипт также
запускает перезапуск его сервиса. Затем проверяется заполнение `access.log`
и предлагается настроить `/etc/logrotate.d/remnanode`.

| Профиль | Ротация |
| --- | --- |
| Малая нода | Ежедневно, 7 архивов |
| Средняя нода | Ежедневно, 3 архива |
| Высокая нагрузка | По достижении 100 МБ, 5 архивов |
| Кастомный конфиг | Редактирование через `nano` |

Стандартные профили обрабатывают `access.log` и `error.log`. После
фактической ротации работающий контейнер `remnanode` перезапускается, чтобы
Xray открыл новые файлы. Для просмотра текущих логов используйте
**Просмотр xlogs** (`docker exec remnanode xlogs`) или **Просмотр логов Xray**
(`tail -f /var/log/remnanode/access.log`). Ctrl+C завершает просмотр.

### Node Precheck

Пункт в первоначальной настройке скачивает и запускает скрипт VPN-HUB от
root. Скрипт проверяет ресурсы VPS, сетевые интерфейсы, порты, firewall и
репутацию IP. Globalping проверяет публичный IP по ICMP и TCP/22 из сетей РФ.
Проверки передают публичный IP внешним сервисам. Замер скорости запрашивает
до 90 МБ у Cloudflare и до 100 МБ у Selectel, а также отправляет до 25 МБ
в Cloudflare. Тест записи на диск по умолчанию выключен.
[Скрипт Node Precheck](https://vpn-hub.pro/static/tools/node-precheck.sh)

### Проверка доступности сервисов

Пункт скачивает закреплённую ревизию DPI Detector, ставит зависимости в
одноразовое окружение Python и запускает программу от root. В ней можно
выбрать проверки доступности сайтов, блокировок HTTP/TLS, подмены DNS и
обрывов TCP. Временные файлы удаляются после завершения.

Требуется Python 3.9 или новее. При необходимости RemnaSuper устанавливает
через APT недостающие системные пакеты, включая подходящий `venv`. Эти
пакеты сохраняются. Для установки зависимостей нужен доступ к GitHub,
репозиториям APT и индексу пакетов Python.
[DPI Detector v4.2.4](https://github.com/Runnin4ik/dpi-detector/releases/tag/v4.2.4)

### iperf3 до российских серверов

Пункт проверяет наличие `iperf3`, `jq`, `ping` и `awk`. Если их нет,
установите соответствующие пакеты Debian/Ubuntu (`iperf3`, `jq`,
`iputils-ping` и, например, `mawk`). RemnaSuper скачивает закреплённый
`speedtest.sh` во временный файл, проверяет SHA-256 и запускает его от root.
[speedtest.sh от ITDog](https://github.com/itdoginfo/russian-iperf3-servers/blob/301b466dd2accd2393524044fbeb56c63c7cd078/speedtest.sh)

Скрипт измеряет задержку и скорость исходящего TCP-трафика до публичных
серверов на портах 5201–5209 и отправляет ICMP-запросы. Колонки `Upload`
и `Download` показывают скорость по данным отправителя и получателя одного
исходящего прогона. Замер может занять канал и израсходовать платный трафик.

Для дополнительных проверок меню запускает внешние скрипты
[Davoyan/ipregion](https://github.com/Davoyan/ipregion),
[IP Check Place](https://IP.Check.Place) и [bench.sh](https://bench.sh).
IP Check Place запускается на английском, а bench.sh измеряет
пропускную способность канала.

### Проверить CPU steal

RemnaSuper за 5 секунд измеряет долю времени, в течение которого гипервизор
не выделял процессорное время VPS. Результат выводится суммарно и по каждому
vCPU на основе счётчиков `/proc/stat`. Менее 2% считается нормой, от 2% до
менее 5% — повышенным значением, от 5% — высоким. Замер выполняется локально.

## Пути и резервные копии

| Назначение | Путь |
| --- | --- |
| Установка и запуск | `/opt/RemnaSuper`, `/usr/local/bin/rs` |
| Резервные копии конфигураций | `/opt/RemnaSuper/backups` |
| Docker Compose и nginx для RemnaNode | `/opt/remnanode/docker-compose.yml`, `/opt/remnanode/nginx.conf` |
| Логи и ротация | `/var/log/remnanode`, `/etc/logrotate.d/remnanode` |
| Geofiles | `/opt/remnanode/geofiles` |
| Отключение IPv6 и правила IPv6 в UFW | `/etc/sysctl.d/zzzz-remnasuper-disable-ipv6.conf`, `/etc/ufw/user6.rules` |
| SMTP | `/etc/systemd/system/remnasuper-smtp-egress.service`, `/opt/RemnaSuper/lib/system/smtp-egress.nft` |
| HAProxy и сборщик | `/etc/haproxy/haproxy.cfg`, `/opt/RemnaSuper/haproxy` |
| nginx и сертификаты заглушки релея | `/etc/nginx/conf.d/remnasuper-relay.conf`, `/etc/nginx/remnasuper-relay-tls` |
| Конфигурация Tor | `/etc/tor/torrc.d/remnasuper.conf` |
| WARP Native | `/opt/warp-native`, `/etc/wireguard/warp.conf` |

Перед изменением Compose RemnaSuper сохраняет копию с именем вида
`docker-compose.yml.bak.YYYY-MM-DD_HHMMSS.XXXXXX`. Точный путь выводится в меню.
Копии HAProxy и снимки SQLite хранятся в `/opt/RemnaSuper/haproxy/backups`.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `RemnaSuper` | Точка входа, загрузка модулей, проверка прав и запуск меню |
| `install.sh`, `VERSION` | Установка из архива GitHub и версия для автообновления |
| `lib/config.sh`, `lib/common.sh`, `lib/ui.sh` | Пути, URL, общие операции и интерфейс меню |
| `lib/update.sh` | Проверка версии, загрузка и установка обновления |
| `lib/menu/` | Главное меню, подменю и подтверждения |
| `lib/system/` | Настройка VPS и сети, сервисы, SSH, релей, сертификаты и диагностика |
| `lib/geofiles/`, `lib/logs/` | Geofiles, подключение логов и настройка ротации |
| `haproxy/collector/`, `haproxy/systemd/` | Сборщик, SQLite-отчёты и unit systemd |
| `icons/` | Графические ресурсы репозитория |

Точка входа загружает через `source` модули `config.sh`, `ui.sh`,
`common.sh`, `update.sh`, `logs.sh`, `system.sh`, `geofiles.sh` и `menu.sh`
в этом порядке. Тематические загрузчики подключают свои подмодули в том же
процессе Bash.

## Проверка изменений

Из корня репозитория проверьте синтаксис всех отслеживаемых Bash-файлов.

```bash
set -e
while IFS= read -r -d '' file; do
    case "$file" in
        RemnaSuper|*.sh) bash -n "$file" ;;
    esac
done < <(git ls-files -z)
```

Если установлен ShellCheck, запустите его из корня репозитория.

```bash
find lib -type f -name '*.sh' -print0 \
  | xargs -0 shellcheck RemnaSuper install.sh
```

Для ручной проверки меню используйте одноразовую Debian/Ubuntu VM и
`sudo REMNASUPER_SKIP_UPDATE=1 ./RemnaSuper`. Проверяйте действия с Docker,
Compose, cron, SSH и firewall на изолированном тестовом сервере.
