# Инвентарь миграции RemnaSuper

Аудит начат 25.11.2026 с чистой ветки `main`, коммит
`da075fbda59ad5f30446876f0a50347246d640e9`, версия 6.27.
Для реализации создана отдельная ветка `tui`.

Машинный инвентарь находится в
[tests/fixtures/action-inventory.json](../tests/fixtures/action-inventory.json).
В нём перечислены файлы исходного checkout, определения Bash и Python,
ссылки на вызывающие функции, ссылки на ресурсы и предполагаемые эффекты.
Статические связи в инвентаре требуют сверки по исходнику при проверке
конкретной ветки. Статическая классификация сама по себе не подтверждает
побочные эффекты, обработку отказа или порядок команд на VM.

| Область | Исходный код | Маршрут в ncurses |
| --- | --- | --- |
| Первоначальная настройка | `lib/menu/setup.sh` | «Нода», типизированные вопросы SSH и порта, внешние скрипты в PTY |
| Ротация логов | `lib/logs/logrotate.sh` | Профили и встроенный редактор, проверка перед записью |
| Geofiles и SMTP | `lib/menu/geofiles.sh`, `lib/menu/smtp_egress.sh` | Действия с прежними Compose, cron и правилами nftables |
| Node Accelerator, WARP и Tor | `lib/menu/{node_accelerator,warp,tor}.sh` | Отдельные разделы, прежние команды и внешние установщики в PTY |
| Psiphon и ss-zapret2 | `lib/menu/{psiphon,zapret}.sh` | Разделы с экземплярами, поля параметров, редактор NFQWS2_OPT |
| HAProxy | `lib/menu/relay*.sh`, `haproxy/collector/` | Отдельные команды состояния, SNI и обслуживания, отчёты из SQLite |
| Диагностика | `lib/menu/main.sh`, `lib/system/network_diagnostics/` | Внешние PTY и типизированные вопросы агента |
| Установка и обновление | `install.sh`, `lib/update.sh` | Независимые установка и запуск `rs-tui`, фоновая проверка версии |

## Отличия исходного checkout от ТЗ

- Пункт «Проверить доступность сервисов» вызывает `run_dpi_detector`.
  Отдельного `run_connectivity_check` в исходном checkout нет.
- `cleanup_logs` и его меню определены и загружены, но ни одна ветка
  исходного меню их не вызывает. Модуль сохранён в исходном дереве.
- В исходном меню уже есть удаление IPv6-правил из UFW и ограничение
  SMTP на 465/587. Эти операции включены в каталог.
- После установки TUI прежняя команда `rs` остаётся доступной.
  Команда TUI — `rs-tui`. Смысл этого решения — возможность оставить
  две установки на одном сервере и независимо выбирать редакцию.
- Код сборщика в работающей службе и все данные остаются по прежнему
  адресу. Для отчётов TUI запускает поставляемый код чтения с каталогом
  данных действующего сборщика. Текстовый CLI сохранён.

## Контракт и проверка

Каталог `lib/backend/actions.json` связывает идентификаторы операций
с разделами, рисками, параметрами и разрешёнными точками входа. Описание
архитектуры, терминала и обновления приведено в [решениях миграции](tui-architecture.md).

GitHub Actions собирает Linux-бинарники на Debian 12/13 и Ubuntu 22.04/24.04
для amd64 и выполняет проверку Bash, Python и программный запуск в PTY.
Первый [прогон сборки и демо](https://github.com/obkaiter/RemnaSuper/actions/runs/45675687703)
успешен по всей матрице.

Приёмка системных изменений, восстановление после отказов, диагностика
между двумя VPS, тесты по реальному SSH, профили терминалов и снимки
экрана требуют дополнительных проверок. Инвентарь не заменяет эти прогоны.
